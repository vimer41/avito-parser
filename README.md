# Avito Radar Bot

**Avito Radar Bot** — программный комплекс для непрерывного высокоскоростного мониторинга и анализа новых объявлений классифайда «Авито» в режиме реального времени. 

Решение предназначено для профессионального использования в сфере арбитража сделок, мониторинга коммерческих закупок, аналитики цен и оперативного уведомления специалистов о поступлении релевантных лотов.

---

## Архитектура и ключевые инженерные решения

Система спроектирована с учетом жестких требований к отказоустойчивости, минимальному потреблению системных ресурсов (оптимизирована для работы в окружениях от 512 МБ ОЗУ) и защите от сетевых ограничений целевой платформы.

### 1. Парсинг данных на основе SSR State (< 5 мс)
* В отличие от традиционных решений, выполняющих ресурсоемкий разбор полного DOM-дерева через BeautifulSoup или lxml, ядро парсера производит прямое извлечение серверного состояния (`__initialData__` / SSR JSON).
* Задержка первичной обработки каталога составляет менее 5 миллисекунд на страницу, исключая избыточную нагрузку на процессор.

### 2. Дедупликация сетевых запросов (URL Normalization & Aggregation)
* Система автоматически нормализует пользовательские поисковые ссылки, отсекая сессионные и трекинговые GET-параметры (`context`, `localPriority`, `searchRadius` и др.).
* Радары пользователей с идентичными поисковыми критериями объединяются в группы: на одну группу выполняется **строго один сетевой запрос**, результаты которого мгновенно распределяются между всеми подписанными клиентами. Это снижает нагрузку на сеть и риск блокировки в 3–5 раз при росте клиентской базы.

### 3. Асинхронный конвейер доставки (Outbox Pattern)
* Мониторинг поисков и доставка сообщений в Telegram полностью изолированы друг от друга через `asyncio.Queue`.
* Сетевые задержки и ограничения Telegram API (включая лимиты `FloodWait`) обрабатываются фоновым воркером со скоростью до 20 сообщений в секунду, не блокируя и не замедляя сканирование радаров.

### 4. Кэширование медиа-дескрипторов Telegram (`file_id`)
* При публикации лота для нескольких пользователей скачивание медиа-контента производится единожды. 
* Полученный `file_id` кэшируется в локальной памяти (LRU-кэш на 2000 записей), а последующие отправки выполняются мгновенно без сетевых расходов на повторный трансфер файлов.

### 5. Обогащение данных через Mobile API
* Интеграция с легковесным эндпоинтом мобильного интерфейса карточки товара (`m.avito.ru/api/1/card/items/{id}`) позволяет извлекать расширенные аналитические метрики лота без загрузки тяжелых HTML-страниц:
  * Статус резервирования лота (`isReserved` — оформление безопасной сделки);
  * Коммерческое платное продвижение (`isPromotion` / VAS-услуги);
  * Счетчики суммарных и суточных просмотров лота;
  * Полный текст описания без ограничений сниппета каталога.

## Комплекс преодоления сетевых барьеров (Anti-Bot Suite)

В систему интегрирован автономный модуль многоуровневого обхода средств защиты от автоматизированного сбора данных:

| Уровень защиты | Механизм нейтрализации | Описание реализации |
| :--- | :--- | :--- |
| **Сетевой уровень (TLS / HTTP/2)** | Эмуляция клиента `curl_cffi` | Полная имитация браузерного стека `Firefox 147` (согласованный шифросьют TLS, аутентичный отпечаток JA3/JA4, HTTP/2 селекторы). |
| **Qrator Security Platform** | XTEA-шифрование и генерация отпечатков | Реализация 32-раундового блочного шифра XTEA для полей `f` и `s`, динамический синтез параметров аппаратного окружения, протокольный обмен `/web/2/ft` и валидация через `/web/1/u`. |
| **Firewall Proof-of-Work (PoW)** | Асинхронный криптографический подбор | Перехват JWT-челленджей из JSON-ответов сервера (коды 429, 439), декодирование сложности и параллельный расчет контрольного значения SHA-256 `nonce`. |
| **Интерактивная капча (GeeTest v4)** | Компьютерное зрение и локальный инференс ONNX | Распознавание координат смещения слайдера и семантических иконок на базе локальной нейросети без передачи данных сторонним платным сервисам решения капч. |
| **Сессионный менеджмент** | Персистентный пул куки | Хранение, валидация и автоматическое сохранение валидных сессионных идентификаторов (`avito_cookies.json`) между перезапусками процесса. |

## Функциональные возможности

* **Мультипользовательская среда и разграничение доступа:**
  * Управление доступом на основе белого списка (Whitelist) с возможностью подачи заявки на верификацию;
  * Дифференциация тарифных планов (`Standart`, `Pro`, `Admin`) с приоритетной очередью обработки лотов;
  * Административная панель управления пользователями, блокировками и мониторингом состояния системы.
* **Тонкая семантическая фильтрация:**
  * Персональные списки стоп-слов (минус-слов) для каждого радара с исключением нерелевантных объявлений (детали, реплики, опт);
  * Черные списки продавцов с возможностью мгновенной блокировки недобросовестных контрагентов в 1 клик под карточкой.
* **Защита от флуда и пакетный контроль:**
  * Детектор возраста лотов с отсевом архивных объявлений, поднятых в ротации;
  * Пакетное подавление спама при первичном запуске поискового запроса (`burst suppression`).
* **Интерактивные элементы управления Telegram:**
  * Прямой переход к объявлению;
  * Быстрое добавление ключевых слов в стоп-лист;
  * Инлайн-блокировка продавца.

| Компонент | Технология | Обоснование выбора |
| :--- | :--- | :--- |

## Развертывание и эксплуатация

### Вариант 1. Развертывание в Docker-контейнере (Рекомендуемый)

1. Клонируйте репозиторий:
   ```bash
   git clone <URL_РЕПОЗИТОРИЯ>
   cd "avito parser tg bot"
   ```

2. Создайте файл переменных окружения `.env`:
   ```bash
   cp .env.example .env
   ```
   Укажите значения обязательных параметров:
   ```env
   BOT_TOKEN=1234567890:ABCdefGHIjklMNOpqrSTUvwxYZ
   ADMIN_ID=123456789
   CHECK_INTERVAL=60
   MAX_SEARCHES_PER_USER=10
   ```

3. Выполните сборку и запуск контейнера в фоновом режиме:
   ```bash
   docker-compose up -d --build
   ```

4. Мониторинг журнала событий:
   ```bash
   docker-compose logs -f
   ```

---

### Вариант 2. Локальная установка и запуск

1. Инициализация виртуального окружения:
   ```bash
   python -m venv venv
   
   # Linux / macOS:
   source venv/bin/activate
   
   # Windows (PowerShell):
   .\venv\Scripts\Activate.ps1
   ```

2. Установка зависимостей:
   ```bash
   pip install --upgrade pip
   pip install -r requirements.txt
   
   # Установка библиотек локального модуля компьютерного зрения (GeeTest v4):
   pip install opencv-python numpy pycryptodome requests ddddocr
   ```

3. Запуск сервиса:
   ```bash
   python bot.py
   ```

---

### Вариант 3. Настройка системной службы Linux (systemd)

Для обеспечения непрерывной работы 24/7 в окружениях Ubuntu/Debian подготовлен файл конфигурации службы [avito-bot.service](file:///c:/Users/zahar/Рабочий%20стол/avito%20parser%20tg%20bot/avito-bot.service):

```bash
# Копирование файла службы
sudo cp avito-bot.service /etc/systemd/system/avito-bot.service

# Перезагрузка конфигурации systemd
sudo systemctl daemon-reload

# Включение автозапуска и старт сервиса
sudo systemctl enable --now avito-bot

# Контроль рабочего статуса
sudo systemctl status avito-bot
```

## Конфигурационные параметры (`.env`)

| Параметр | Тип | Обязательный | Описание |
| :--- | :---: | :---: | :--- |
| `BOT_TOKEN` | String | Да | Аутентификационный токен Telegram-бота, полученный у `@BotFather`. |
| `ADMIN_ID` | Integer | Да | Telegram ID главного администратора системы. |
| `CHECK_INTERVAL` | Integer | Нет | Интервал между кругами сканирования радаров в секундах (по умолчанию: `60`). |
| `MAX_SEARCHES_PER_USER` | Integer | Нет | Базовый лимит активных радаров на одного пользователя (по умолчанию: `10`). |
| `PROXY_URL` | String | Нет | URL HTTP/SOCKS5 прокси-сервера (при необходимости маршрутизации трафика). |

## Структурная организация проекта

```text
├── bot.py                     # Точка входа приложения, инициализация диспетчера и фоновых задач
├── config.py                  # Модуль валидации и загрузки параметров конфигурации
├── database.py                # Слой абстракции базы данных SQLite (пользователи, радары, история лотов)
├── parser.py                  # Движок сбора данных (SSR JSON экстрактор, mobile API, anti-bot интеграция)
├── scheduler.py               # Координатор циклов мониторинга и асинхронный воркер очереди Outbox
├── middlewares.py             # Middleware контроля доступа (Whitelist) и аудита пользовательских событий
│
├── anti_bot/                  # Модуль нейтрализации систем сетевой защиты
│   ├── manager.py             # Центральный диспетчер протоколов обхода (QRATOR, PoW, GeeTest)
│   ├── qrator_payload_codec.py# Реализация криптографического алгоритма XTEA
│   ├── generate_qrator_variants.py # Генератор синтетических браузерных отпечатков
│   ├── firewallpow_payload_reference.py # Алгоритм решения Proof-of-Work задач
│   ├── base.txt / base-s.json # Эталонные структуры аппаратных профилей
│   └── GeekedTest/            # Локальный ONNX-пакет решения капчи GeeTest v4
│
├── handlers/                  # Модули обработки входящих Telegram-событий
│   ├── common.py              # Регистрация, верификация, справочная информация
│   ├── searches.py            # Управление радарами, настройка стоп-слов и параметров поиска
│   ├── profile.py             # Личный кабинет пользователя, статистика и тарифный статус
│   └── admin.py               # Инструменты администрирования, управление доступом и рассылки
│
├── Dockerfile                 # Инструкция сборки базового контейнера приложения
├── docker-compose.yml         # Спецификация многоконтейнерного развертывания
├── avito-bot.service          # Юнит-файл для управления процессом через systemd
└── requirements.txt           # Реестр внешних программных зависимостей Python
```
