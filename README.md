# ⚡️ AVITO RADAR

**AVITO RADAR** — профессиональный программный комплекс и Telegram-бот для непрерывного высокоскоростного перехвата новых объявлений на классифайде «Авито» в режиме реального времени с масштабированием до 300 уникальных радаров.

Комплекс спроектирован для байеров, специалистов по перепродаже и мониторинга закупок. Все уникальные нормализованные URL опрашиваются с единым целевым интервалом **15–20 секунд** независимо от тарифа пользователя, а тариф определяет задержку и приоритет доставки уведомления.

Актуальная архитектура 300 радаров, пул прокси, расчёт ёмкости для 25–300 URL и SLA доставки: **[SCALING_AND_RELIABILITY.md](SCALING_AND_RELIABILITY.md)**.

## 🎯 Модель доступа и тарифная сетка

Бот работает по прозрачной модели подписок с мгновенным автоматическим стартом для новых клиентов:

| Тариф | Лимит радаров | Опрос URL | Задержка доставки | Функционал | Стоимость |
| :--- | :---: | :---: | :---: | :--- | :---: |
| **🎁 Бесплатный триал** | **1 радар** | **15–20 с** | **1.5 с** | Автоматический старт на 6 часов: цена и ссылка, стоп-слова, быстрый отклик, ЧС | **Бесплатно (6 ч)** |
| **⚡️ STANDART** | **4 радара** | **15–20 с** | **1.0 с** | Функции триала, до 4 независимых поисков, отправка фото по URL | **170 ⭐ / 30 дней** |
| **🔥 PRO** | **9 радаров** | **15–20 с** | **0.0 с (мгновенно)** | Standart + высший приоритет очереди + догон до 10 свежих лотов после паузы (до 30 мин) | **470 ⭐ / 30 дней** |
| **👑 ADMIN** | `MAX_SEARCHES_PER_USER` (по умолчанию 20) | **15–20 с** | **0.0 с (мгновенно)** | Все возможности PRO + управление ботом, `/stats`, `/reload_proxies`, экспорт БД и логов | Доступ администратора |

> [!NOTE]
> Все сроки действия подписок и триалов отображаются в **Московском часовом поясе (UTC+3, МСК)** с точным обратным отсчетом времени до окончания.

Целевой интервал 15–20 с достигается при достаточном числе здоровых статических прокси в пуле (`proxies.txt`). При дефиците прокси планировщик автоматически переходит в режим `degraded`, честно увеличивая интервал без падения сервиса и без накопления вечного бэклога.

### Оплата только Telegram Stars

- `STARS_PAYMENTS_ENABLED=0` по умолчанию; `1` включает checkout. Тарифы: Базовый (`lite`, 1 радар, раз в 40 с, `STARS_PRICE_BASIC=199`), Средний (`standart`, 2 радара, раз в 30 с, `STARS_PRICE_MEDIUM=449`), Полный (`pro`, 4 радара, раз в 20 с, `STARS_PRICE_FULL=899`). Ссылку, которую ведут несколько тарифов, бот проверяет с интервалом самого быстрого. Срок — 30 дней, разовая оплата **без автосписания**. Provider token не нужен.
- Путь: **💳 Тарифы → тариф → Оплатить → счёт Telegram**. При выключенных платежах кнопки checkout нет; старые кнопки карты/криптовалюты открывают новый экран Stars.
- Счёт привязан к Telegram ID, сумме и тарифу; действителен час. Pre-checkout проверяет цену и резервирует один счёт, но **не выдаёт доступ**. Только `successful_payment` атомарно записывает уникальный Telegram charge ID и продлевает подписку. Повтор события не добавляет срок; начатые платежи обрабатываются и после выключения продаж.
- 30 дней добавляются к оставшемуся сроку подписки / триала; выбранный тариф применяется сразу ко всему сроку, включая смену PRO на Standart. При истёкшем доступе отсчёт начинается с оплаты.
- `/terms` — условия, `/paysupport` — обращение по оплате / возврату, доступное после окончания подписки. Финансовые записи сохраняются при ручном удалении пользователя для сверки и защиты от повторного платежного события.
- Админка: **👤 Подписка / платежи → ⭐ Платежи / возврат → заказ → подтверждение**. Возврат выполняется через `refundStarPayment`. Повтор запроса безопасен; сетевой неопределённый ответ требует повторной сверки через 5 минут. Последнее неизменённое продление отменяется автоматически; более поздние платежи / ручные изменения не перезаписываются, ставится отметка для сверки срока поддержкой.
- Для текущего VPS задайте Actions Variable `STARS_PAYMENTS_ENABLED=1`. Деплой атомарно меняет эту настройку `.env`, не выводя токены; старые `STARS_PRICE_STANDART/PRO`, которые он ещё пишет, бот больше не читает — цены задаются `STARS_PRICE_BASIC/MEDIUM/FULL`. При неудачной активации возвращаются прежние настройки.

### 1. Парсинг данных через SSR JSON State (< 5 мс) и Fast-Skip
Вместо медленного разбора тяжелого DOM-дерева ядро парсера напрямую извлекает серверное состояние (`__initialData__` / SSR JSON). Если первые 3 ID объявлений на первой странице совпадают с предыдущим сканом (`last_top_ids`) и все радары источника уже откалиброваны, вторая страница и обращение к БД пропускаются (`fast-skip`).

### 2. Быстрая доставка и поддержка фотографий
- При наличии Telegram `file_id` в LRU-кэше мгновенно отправляется фото из кэша.
- Для тарифов **PRO / Standart** при наличии `image_url` выполняется прямая отправка `send_photo(photo=image_url)` без скачивания изображения ботом; при ошибке CDN карточка мгновенно уходит текстом.
- Для базового/триального тарифа при отсутствии `file_id` в кэше сразу отправляется текстовая карточка.

### 3. Строгая пользовательская дедупликация и защита от гонок
- **Exact-source collection**: Совпадающие нормализованные URL собираются один раз для всех подписчиков.
- **Дедупликация `(user_id, item_id)`**: Один и тот же лот никогда не отправляется одному пользователю дважды, даже если совпали несколько его радаров. Если до захвата события воркером лот подошёл нескольким радарам пользователя, их названия объединяются в одно уведомление.
- **Persistent Outbox (`notification_events`)**: Только подтверждённая доставка в Telegram фиксирует `seen_items` для всех совпавших радаров пользователя. При падении процесса во время отправки после рестарта ставится пометка `ℹ️ Возможен повтор после перезапуска сервиса`.

### 4. 🕒 Догон пропущенных объявлений после паузы (PRO / Admin)
Если источник не сканировался дольше порога свежести из-за перезапуска или сетевой паузы, для подписчиков **PRO / Admin** окно свежести временно расширяется до **30 минут** (до 3 страниц каталога). Доставляются не более **10 самых свежих** пропущенных лотов с пометкой `🕒 найдено после паузы`, а более старые объявления из окна простоя автоматически помечаются в `seen_items`.

### 5. 🔍 Выбор области поиска (Только в заголовке / Заголовок + Описание)
Каждый радар можно гибко переключать в 1 клик:
- `Только в названии` (`bt=1`) — максимальная точность, отсекаются случайные упоминания в тексте описания.
- `В названии и описании` — максимальный охват для редких позиций и запчастей.

### 6. 💬 Встроенная служба поддержки (Helpdesk / Ticket System)
Пользователи могут отправить вопрос, скриншот, квитанцию об оплате, голосовое или документ прямо в чат с ботом по кнопке **«💬 Поддержка»**. Администраторы получают карточку обращения с кнопкой `[ ✍️ Ответить ]` и ведут переписку с пользователем прямо через интерфейс бота.

### 7. 📱 Эргономика интерфейса: SPA Single-Page Navigation
Все переходы по разделам меню, профилю, тарифам и настройкам радаров выполняются на месте (`edit_text`) без спама сотнями сообщений в истории диалога. В каждом меню предусмотрены кнопки `[ 🔙 Назад ]` и `[ 🏠 В главное меню ]`.

## 🛡 Комплекс преодоления сетевых защит (Anti-Bot Suite)

В систему встроен автономный модуль нейтрализации систем защиты:

| Защита | Механизм нейтрализации | Описание |
| :--- | :--- | :--- |
| **TLS / HTTP/2 Fingerprint** | Эмуляция `curl_cffi` (`AsyncSession`) | Имитация профиля актуального браузера (совпадающий шифросьют TLS, аутентичные JA3/JA4, HTTP/2 селекторы). |
| **Qrator Security Platform** | XTEA-кодек и генерация фингерпринтов | 32-раундовый шифр XTEA для полей `f` и `s`, динамический синтез параметров WebGL/Canvas, протокольный обмен `/web/2/ft` и `/web/1/u`. |
| **Proof-of-Work (PoW)** | Асинхронный криптоподбор | Перехват JWT-челленджей из ответов 429/439 и параллельный расчет контрольного значения SHA-256 `nonce`. |
| **GeeTest v4** | Ленивый локальный ONNX-инференс | Распознавание координат слайдера и семантических иконок локальной нейросетью без платных внешних сервисов (ленивая загрузка весов при первом вызове). |
| **Пул статических прокси** | Изоляция сессий и карантин (`proxy_pool.py`) | Раздельные `AsyncSession`, куки `data/cookies/cookies_<proxy_id>.json`, карантин и half-open восстановление для каждого прокси из `proxies.txt`. |

## ⚙️ Установка и запуск

### 1. Быстрый запуск на Linux VPS (systemd)

1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/vimer41/avito-tracker2.git /opt/avito_parser_bot
   cd /opt/avito_parser_bot
   ```
2. Создайте виртуальное окружение и установите зависимости:
   ```bash
   python3 -m venv venv
   source venv/bin/activate
   pip install --upgrade pip
   pip install -r requirements.txt
   ```
3. Создайте файл `.env` (см. `.env.example`) и список прокси `proxies.txt` (по одному `http://user:pass@ip:port` или `socks5://user:pass@ip:port` на строку). Если `proxies.txt` отсутствует, используется `PROXY_URL` из `.env`.
4. Установите и запустите службу `avito-bot.service`:
   ```bash
   sudo cp avito-bot.service /etc/systemd/system/avito-bot.service
   sudo systemctl daemon-reload
   sudo systemctl enable --now avito-bot
   sudo systemctl status avito-bot
   ```

### 2. Безопасные локальные проверки

```bash
python -m pip install -r requirements.txt
python -m pip check
python -B tools/check_syntax.py
python -B tools/run_offline_tests.py
```

Тесты используют временные директории, не читают `.env` и не запускают бота. Внешние сетевые сокеты и HTTP-клиенты заблокированы.

## 👑 Команды администратора

- `/admin` или `👑 Админ-панель` — Сводная статистика, управление доступом, список пользователей с их тарифами и остатком времени.
- `/stats` — Подробная телеметрия за 15 и 60 минут: состояние пула прокси, расчёт ёмкости и дефицита прокси, перцентили `p50/p95/p99` сканирования и доставки по тарифам (`deliver_at -> t_sent` и `t_queued -> t_sent`), доля `fast-skip`, глубина очереди `outbox` и `RSS` памяти.
- `/reload_proxies` — Горячая перезагрузка файла `proxies.txt` и `PROXY_URL` без остановки бота и без потери состояния.
- `/db` или `/backup` — Мгновенное скачивание резервной копии базы данных SQLite (WAL-безопасная копия через SQLite Online Backup API).
- `/delete_user @username` или `/purge_user <ID>` — Удаление профиля, радаров и их истории; финансовые записи Stars сохраняются для возвратов и защиты от повторного события.
