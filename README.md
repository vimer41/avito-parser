# ⚡️ AVITO RADAR

**AVITO RADAR** — профессиональный программный комплекс и Telegram-бот для непрерывного высокоскоростного перехвата новых объявлений и аналитики снижения цен на классифайде «Авито» в режиме реального времени.

Комплекс спроектирован для байеров, специалистов по перепродаже и мониторинга закупок. Скорость обнаружения зависит от числа уникальных поисков, общего HTTP-бюджета и доступности Авито. После обнаружения уведомление с ценой и ссылкой отправляется без ожидания скачивания фото.

Актуальная архитектура, настройки ограничения запросов, офлайн-модель 350 подписок и ограничения покрытия: **[SCALING_AND_RELIABILITY.md](SCALING_AND_RELIABILITY.md)**. Целевые интервалы не являются гарантией и не задают разрешённую частоту Авито.

## 🎯 Модель доступа и тарифная сетка

Бот работает по прозрачной модели подписок с мгновенным автоматическим стартом для новых клиентов:

| Тариф | Лимит радаров | Интервал | Функционал | Стоимость |
| :--- | :---: | :---: | :--- | :---: |
| **🎁 Бесплатный триал** | **1 радар** | `CHECK_INTERVAL` | Автоматический старт на 6 часов: цена и ссылка, стоп-слова, быстрый отклик, ЧС | **Бесплатно (6 ч)** |
| **⚡️ STANDART** | **4 радара** | `CHECK_INTERVAL` | Функции триала, до 4 независимых поисков | **170 ⭐ / 30 дней** |
| **🔥 PRO** | **9 радаров** | `min(15, CHECK_INTERVAL)` | Standart + алерты на снижение цен, ускоренный целевой интервал | **470 ⭐ / 30 дней** |
| **👑 ADMIN** | `MAX_SEARCHES_PER_USER` (по умолчанию 20) | как PRO | Управление ботом, экспорт БД и логов, поддержка | Доступ администратора |

> [!NOTE]
> Все сроки действия подписок и триалов отображаются в **Московском часовом поясе (UTC+3, МСК)** с точным обратным отсчетом времени до окончания.

Интервалы целевые: задержка сети, нагрузка, общий HTTP-бюджет и блокировки Авито могут увеличить реальный период. Сравнение скорости с конкурентами не гарантируется.

### Оплата только Telegram Stars

- `STARS_PAYMENTS_ENABLED=0` по умолчанию; `1` включает checkout. `STARS_PRICE_STANDART=170`, `STARS_PRICE_PRO=470`; срок — 30 дней, разовая оплата **без автосписания**. Provider token не нужен.
- Путь: **💳 Тарифы → Standart / PRO → условия → согласен — оплатить → счёт Telegram**. При выключенных платежах кнопки checkout нет; старые кнопки карты/криптовалюты открывают новый экран Stars.
- Счёт привязан к Telegram ID, сумме и тарифу; действителен час. Pre-checkout проверяет цену и резервирует один счёт, но **не выдаёт доступ**. Только `successful_payment` атомарно записывает уникальный Telegram charge ID и продлевает подписку. Повтор события не добавляет срок; начатые платежи обрабатываются и после выключения продаж.
- 30 дней добавляются к оставшемуся сроку подписки / триала; выбранный тариф применяется сразу ко всему сроку, включая смену PRO на Standart. При истёкшем доступе отсчёт начинается с оплаты.
- `/terms` — условия, `/paysupport` — обращение по оплате / возврату, доступное после окончания подписки. Финансовые записи сохраняются при ручном удалении пользователя для сверки и защиты от повторного платежного события.
- Админка: **👤 Подписка / платежи → ⭐ Платежи / возврат → заказ → подтверждение**. Возврат выполняется через `refundStarPayment`. Повтор запроса безопасен; сетевой неопределённый ответ требует повторной сверки через 5 минут. Последнее неизменённое продление отменяется автоматически; более поздние платежи / ручные изменения не перезаписываются, ставится отметка для сверки срока поддержкой.
- Для текущего VPS задайте Actions Variables `STARS_PAYMENTS_ENABLED=1`, `STARS_PRICE_STANDART=170`, `STARS_PRICE_PRO=470`. Деплой атомарно меняет только эти настройки `.env`, не выводя токены. При неудачной активации возвращаются прежние настройки.

## 🛠 Ключевые инженерные решения и архитектура

Потребление ресурсов и достижимые интервалы необходимо измерять на целевом VPS; гарантии скорости для 350 разных поисков нет.

```
                    ┌────────────────────────────────────────────────────────┐
                    │                      АВИТО (AVITO)                     │
                    └───────────────────────────┬────────────────────────────┘
                                                │
                                    HTTP/2, TLS Chameleon
                                                │
                                                ▼
                    ┌────────────────────────────────────────────────────────┐
                    │            CORE PARSER ENGINE (parser.py)              │
                    │  • Извлечение SSR JSON State (__initialData__) < 5 ms  │
                    │  • Обогащение через Mobile API (/api/1/card/items)     │
                    │  • Anti-Bot Suite (Qrator XTEA, PoW, GeeTest v4 ONNX)  │
                    └───────────────────────────┬────────────────────────────┘
                                                │
                                                ▼
                    ┌────────────────────────────────────────────────────────┐
                    │          SCHEDULER & PIPELINE (scheduler.py)           │
                    │  • Дедупликация URL и группировка радаров              │
                    │  • Семантическая фильтрация (стоп-слова, ЧС)           │
                    │  • Детекция снижения цен (Price Drop Alert)            │
                    │  • Справедливые дедлайны и отложенные повторы         │
                    │  • Общий HTTP-бюджет и cooldown для всех сессий       │
                    └───────────────────────────┬────────────────────────────┘
                                                │  Persistent Outbox (SQLite)
                                                ▼
                    ┌────────────────────────────────────────────────────────┐
                    │         OUTBOX DELIVERY DISPATCHER & TG BOT            │
                    │  • LRU/TTL кэширование file_id (RAM)                   │
                    │  • Доставка до 20 сообщений в секунду с Flood-контролем│
                    │  • Telegram Bot (aiogram 3.x, SPA in-place navigation) │
                    └────────────────────────────────────────────────────────┘
```

### 1. Парсинг данных через SSR JSON State (< 5 мс)
Вместо медленного разбора тяжелого DOM-дерева через BeautifulSoup/lxml ядро парсера напрямую извлекает серверное состояние (`__initialData__` / SSR JSON). Задержка парсинга составляет менее 5 мс на страницу, процессор свободен от лишней нагрузки.

### 2. Доставка без ожидания фотографий
- При наличии Telegram `file_id` отправляется готовое фото из кэша.
- Иначе сразу отправляется текстовая карточка с ценой и ссылкой; загрузка CDN не задерживает уведомление.
- Фоновое обогащение фотографиями пока не реализовано. Вспомогательный загрузчик `aiohttp`, если вызывается отдельно, также соблюдает общий HTTP-бюджет.

### 3. Защита от спама и гонки состояний (Anti-Race & Cache Stampede)
- **Exact-source collection**: Совпадающие нормализованные URL собираются один раз для всех подписчиков. Создание радара и исходного списка `seen_items` — одна транзакция.
- **RAM LRU/TTL Cache**: Известные Telegram `file_id` переиспользуются без сетевой загрузки фото. Краткоживущие снимки источника используются для калибровки одинаковых поисков.
- **Persistent Outbox**: Уведомление сначала записывается в SQLite. Только подтверждённая доставка фиксирует `seen_items` / новую цену. Сетевые ошибки и FloodWait оставляют задачу для повтора; брошенная после сбоя задача возвращается в работу по истечении lease.
- Семантика доставки — **at least once**, не exactly once: при падении между ответом Telegram и подтверждением в SQLite возможен повтор. Свежесть фиксируется при обнаружении; время в очереди не приводит к удалению принятого уведомления. Неизвестный возраст не записывается в `seen_items`.

### 4. 📉 Отслеживание снижения цен продавцов (Price Drop Alert) 💎
Эксклюзивная функция тарифа **PRO**:
- Бот запоминает первоначальную цену каждого лота в таблице `seen_items`.
- Если продавец сбрасывает цену на заданный процент (-5%, -10%, -15%, -20%, -30%, -50% или **любой свой от 1% до 99%**), бот мгновенно отправляет повторный пуш с расчетом чистой выгоды в рублях:
  `📉 СНИЖЕНИЕ ЦЕНЫ · AVITO RADAR [-15%]`  
  `🏷 85 000 ₽ (было 100 000 ₽ · выгода 15 000 ₽)`

### 5. 🔍 Выбор области поиска (Только в заголовке / Заголовок + Описание)
Каждый радар можно гибко переключать в 1 клик:
- `Только в названии` — максимальная точность, отсекаются случайные упоминания в тексте описания.
- `В названии и описании` — максимальный охват для редких позиций и запчастей.

### 6. 💬 Встроенная служба поддержки (Helpdesk / Ticket System)
Пользователи могут отправить вопрос, скриншот, квитанцию об оплате, голосовое или документ прямо в чат с ботом по кнопке **«💬 Поддержка»**. Администраторы получают карточку обращения с кнопкой `[ ✍️ Ответить ]` и ведут переписку с пользователем прямо через интерфейс бота.

### 7. 📱 Эргономика интерфейса: SPA Single-Page Navigation
Все переходы по разделам меню, профилю, тарифам и настройкам радаров выполняются на месте (`edit_text`) без спама сотнями сообщений в истории диалога. В каждом меню предусмотрены кнопки `[ 🔙 Назад ]` и `[ 🏠 В главное меню ]`.

## 🛡 Комплекс преодоления сетевых защит (Anti-Bot Suite)

В систему встроен автономный модуль нейтрализации систем защиты:

| Защита | Механизм нейтрализации | Описание |
| :--- | :--- | :--- |
| **TLS / HTTP/2 Fingerprint** | Эмуляция `curl_cffi` | Имитация профиля актуального браузера (совпадающий шифросьют TLS, аутентичные JA3/JA4, HTTP/2 селекторы). |
| **Qrator Security Platform** | XTEA-кодек и генерация фингерпринтов | 32-раундовый шифр XTEA для полей `f` и `s`, динамический синтез параметров WebGL/Canvas, протокольный обмен `/web/2/ft` и `/web/1/u`. |
| **Proof-of-Work (PoW)** | Асинхронный криптоподбор | Перехват JWT-челленджей из ответов 429/439 и параллельный расчет контрольного значения SHA-256 `nonce`. |
| **GeeTest v4** | Локальный ONNX-инференс | Распознавание координат слайдера и семантических иконок локальной нейросетью без платных внешних сервисов. |
| **Сессионный пул** | Валидация куки | Хранение и автопродление сессионных куки в `avito_cookies.json`. |

## 🚀 CI/CD Pipeline и автоматический деплой

Проект оснащен полноценным конвейером непрерывной интеграции и доставки на базе **GitHub Actions** (`.github/workflows/deploy.yml`):

1. **Автоматическое тестирование (Test Suite)**:
   При каждом `git push` в ветки `feature/json-api` или `main` автоматически прогоняются 7 изолированных асинхронных тестов (`tests/test_system.py`):
   - Проверка выдачи 5h триала новым юзерам;
   - Проверка лимитов радаров (триал: 1, стандарт: 4, про: 9, админ: max);
   - Валидация форматирования дат в часовом поясе МСК;
   - Проверка полного каскадного удаления пользователей;
   - Проверка TTL-кэша и замков против гонки состояний;
   - Проверка компиляции всего исходного кода (`py_compile`).
2. **Автоматический деплой на VPS (Deploy Job)**:
   При успешном прохождении тестов GitHub Actions по SSH подключается к вашему серверу, обновляет репозиторий, устанавливает зависимости и бесшовно перезапускает сервис `avito-bot.service` через systemd.

## ⚙️ Установка и запуск

### 1. Быстрый запуск на Linux VPS (systemd)

1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/vimer41/avito-tracker2.git /opt/avito_parser_bot
   cd /opt/avito_parser_bot
   ```
2. Создайте виртуальное окружение и установите зависимости:
   ```bash
   python3 -m venv venv
   source venv/bin/activate
   pip install --upgrade pip
   pip install -r requirements.txt
   ```
3. Создайте файл `.env`:
   ```env
   BOT_TOKEN=1234567890:AAExampleTokenHere
   ADMIN_ID=986832959
   ADMIN_IDS=986832959,455386428
    CHECK_INTERVAL=25
    MAX_SEARCHES_PER_USER=20
   MAX_CONCURRENT_WORKERS=3
    STARS_PAYMENTS_ENABLED=0
    STARS_PRICE_STANDART=170
    STARS_PRICE_PRO=470
   ```
4. Установите и запустите службу `avito-bot.service`:
   ```bash
   sudo cp avito-bot.service /etc/systemd/system/avito-bot.service
   sudo systemctl daemon-reload
   sudo systemctl enable --now avito-bot
   sudo systemctl status avito-bot
   ```

### 2. Настройка автоматического деплоя (CI/CD)

В репозитории GitHub перейдите в **Settings -> Secrets and variables -> Actions** и добавьте:
- `VPS_HOST` — IP-адрес вашего сервера;
- `VPS_USERNAME` — логин (обычно `root`);
- `VPS_PASSWORD` — пароль к серверу (или `VPS_SSH_KEY`).

Пуш в `feature/json-api` или `main` запускает тесты и затем деплой. Pull request запускает только тесты. Развёртывается **точный SHA**, прошедший проверки, а не последняя версия произвольной ветки. Устаревший workflow пропускает деплой, если появился более новый коммит.

На VPS сначала создаётся отдельное Python-окружение, проверяются версия Python, зависимости (`pip check`) и синтаксис всех Python-файлов. **Временно включён минимальный серверный preflight:** полный повтор офлайн-тестов на VPS пропускается, но в GitHub CI весь набор по-прежнему обязателен на Python 3.11 и 3.12. Версия Python, доступная память и состояние службы выводятся в лог. Ошибка до активации не останавливает бота; неиспользованное новое окружение удаляется.

Для возврата полного повтора на VPS установите переменную GitHub Actions `DEPLOY_FULL_TESTS=1` в **Settings -> Secrets and variables -> Actions -> Variables**. При прямом запуске скрипта полная проверка включена по умолчанию; `DEPLOY_FULL_TESTS=0` оставляет минимальный preflight. В полном режиме нативные пулы OpenBLAS/OpenMP/MKL тестового процесса ограничены одним потоком, лимит тестов — 600 секунд с принудительным завершением через дополнительные 30 секунд.

После успешной проверки бот останавливается, SQLite копируется через Backup API в `backups/`, меняются код и окружение. Проверяется, что systemd-сервис остаётся активным 20 секунд без перезапусков. При ошибке возвращаются предыдущие код и окружение; БД автоматически не перезаписывается. Это проверка стабильности процесса, а не готовности парсера или доступности Telegram/Avito. Автоматического удаления пользователей и очистки их логов нет.

Серверу нужны Python 3.11 или 3.12 с `venv`, `bash`, `git`, `tar`, `flock`, GNU `timeout` и права на управление `avito-bot` через systemd. Скрипт предпочитает `python3.11`, иначе использует `python3`; другие версии отклоняются до установки зависимостей. Обе поддержанные версии проходят Linux CI. Рабочая директория службы должна совпадать с `/opt/avito_parser_bot` или `/opt/avito-bot`. При необходимости добавьте секрет `VPS_HOST_FINGERPRINT` для проверки ключа SSH-сервера.

После успешной активации включена консервативная очистка (`DEPLOY_CLEANUP=1`): минимум 4 последних окружения и 7 SQLite-бэкапов, удаление только старше 7 / 14 дней соответственно. Активное, последнее rollback-окружение и бэкап текущего деплоя защищены независимо от возраста; симлинки не обходятся при удалении. Неизвестные файлы, `.env`, рабочая БД и логи не очищаются. Actions Variables: `DEPLOY_KEEP_RELEASES`, `DEPLOY_KEEP_BACKUPS`, `DEPLOY_RELEASE_MIN_AGE_DAYS`, `DEPLOY_BACKUP_MIN_AGE_DAYS`. Минимум разрешено 2 окружения и 3 бэкапа; ошибка очистки не откатывает работающий деплой. Предпросмотр вручную: `python -B tools/cleanup_releases.py --target /opt/avito_parser_bot`; удаление только с `--apply` и под deploy-lock.

`PRODUCTION_DIAGNOSTICS=1` запускает после деплоя дополнительную проверку: установленный SHA, systemd, ресурсы, SQLite quick_check, агрегаты сканирования Авито и Telegram API. `DIAGNOSTICS_NOTIFY_ADMIN=1` отправляет основному администратору диагностическую кнопку. Только нажатие настоящим пользователем подтверждает обработку входящего запроса; `sendMessage` подтверждает приём сообщения API, не его прочтение. Метрики берутся из ограниченного хвоста логов и не доказывают долговременную стабильность. Отдельный workflow `VPS production diagnostics` доступен вручную, когда файл workflow присутствует в основной ветке.

### 3. Безопасные локальные проверки

```bash
python -m pip install -r requirements.txt
python -m pip check
python -B tools/check_syntax.py
python -B tools/run_offline_tests.py
```

Тесты используют временные директории, не читают `.env` и не запускают бота. HTTP-клиенты заблокированы; внутренний loopback-канал `asyncio` разрешён. Docker-контекст исключает токены, базы, cookies, логи и локальные окружения.

### 4. Ограничения антибота и доступа

- Firewall PoW ограничен 5 секундами / 2 000 000 попыток и принимает только сложность 0–64 hex-цифры. Отмена асинхронного запроса передаётся вычисляющему потоку; уже начатый HTTP-запрос завершается в пределах его таймаута.
- GeeTest: исправлена проверка неполного полубайта PoW, модели инициализируются лениво один раз, неполное распознавание не дополняется случайными координатами. `pt=2` не реализован и отклоняется явно.
- QRATOR остаётся **best effort**: используется синтетический эталонный отпечаток, скачанный JS не исполняется. Полученный токен не считается успешным доступом: парсер заново проверяет целевую страницу в той же сессии. Live-процент успешного прохождения защит не измерялся.
- На запрос разрешены не более двух этапов решения. Неустранённая защита включает общий cooldown для сессий с тем же настроенным соединением, учитывая `Retry-After`. Разные сессии не означают разные внешние IP; увеличение количества воркеров не гарантирует обход блокировок.
- `PROXY_URL` используется при добавлении радара и в мониторинге; Firefox User-Agent согласован с сетевым профилем. Cookie-файлы разделяются по прокси, сохраняют домен, путь, secure и срок действия.
- `is_allowed=1` без даты означает ручной бессрочный доступ. Если дата есть, доступ заканчивается по `subscription_until`, включая старые оплаченные записи. Ручное одобрение очищает дату, отзыв прекращает подписку / триал. Лимит радаров проверяется транзакционно.

## 👑 Команды администратора

- `/admin` или `👑 Админ-панель` — Сводная статистика, управление доступом, список пользователей с их тарифами и остатком времени.
- **👤 Подписка / платежи → 💳 Выдать / продлить → Standart / PRO → 1 / 7 / 30 / 90 дней → подтверждение**. Повторное подтверждение одной выдачи не продлевает срок дважды. Ручная выдача не обозначается как подтверждённая оплата Stars.
- **⭐ Платежи / возврат** в карточке пользователя — история заказов и подтверждаемый возврат Stars.
- `/db` или `/backup` — Мгновенное скачивание резервной копии базы данных SQLite (WAL-безопасная копия через SQLite Online Backup API).
- `/delete_user @username` или `/purge_user <ID>` — Удаление профиля, радаров и их истории; финансовые записи Stars сохраняются для возвратов и защиты от повторного события.
- Выгрузка системных логов в Telegram в виде ZIP-архива в 1 клик прямо из панели управления.
